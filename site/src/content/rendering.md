# 描画とガラス

ame-shell は GUI ツールキット(Qt・GTK)を使わず、**自前の GPU 描画**で UI を描きます。OpenGL ES 3 の 2D レンダラは `src/gfx.zig` にあり、**インスタンス描画する 1 種類の四角形**と SDF(符号付き距離場)だけで、角丸・影・円弧・グラデーション・文字・ガラスまでを描きます。

## 1 種類の四角形ですべてを描く {#quads}

- パネル・ボタン・影・円グラフ・線・文字のグリフは、どれも「四角形 1 枚 + 形の種類 + パラメータ」として配列に積み、まとめて 1 回の描画命令で送ります。
- 角丸や円は、ピクセルシェーダが**距離場**から計算します。そのため拡大してもにじまず、輪郭は 1 ピクセル単位でなめらかです。
- 影もシェーダが角丸の距離場からその場で計算します。ぼかし用のテクスチャやぼかしの処理は使いません。
- `ui-scale`(既定 1.25)や画面の拡大率を変えても、すべて同じ式で描き直すだけです。

## 文字 {#text}

```
fontconfig(書体を探す) → HarfBuzz(並べる・合字) → FreeType(輪郭) → SDF → 共有グリフアトラス
```

- 日本語の UI 書体(既定は Noto Sans CJK JP)、アイコン用の Nerd Font、足りない文字は fontconfig で探した書体、の順で使います。
- グリフは SDF にして 1 枚のアトラスにまとめ、**どの大きさでもくっきり**描きます。発光(glow)も同じ SDF から作ります。
- 初めて開くランチャーで 100 字ほど一度に必要になっても待たないよう、アイドル時間に先読みしておきます。アウトラインから SDF を作る方法を改良して、1 字 6.6 ms から 2.2 ms にしました。

## ガラス {#glass}

::img shot-dashboard.jpg | ダッシュボードのガラス。真後ろの壁紙がぼけて透け、縁で光が曲がります

1. 壁紙を出力ごとの FBO(`Backdrop.scene`)に描きます。
2. **dual Kawase**(縮小 × N 回、拡大 × 1 回)でぼかした画像を持っておきます。ガウスぼかしより少ない計算で、同じくらい大きくぼかせます。
3. パネルのシェーダは、自分が画面上のどこにあるか(`u_origin`)を足して、**自分の真後ろ**のぼけた壁紙を読みます。
4. 縁では SDF の勾配を「法線」として使い、読む位置を少しずらします(**屈折**)。さらに R・G・B を少しずつずらし(**色収差**)、左上からの光で縁を光らせ(**ハイライト**)、細かいノイズと**きらめき**を足します。

設定の `theme { blur 3  refraction 10  sparkle 0.7  tint-strength 0.42 }` で、ぼかし・屈折・きらめき・色の濃さを変えられます。保存した瞬間に反映されます。

>! 他のアプリの**窓越し**にぼかすことはできません。コンポジタ(River)が「窓の後ろをぼかす」仕組み(`ext_background_effect`)を提供していないためです。窓の上に出るポップアップは、色を濃くして読みやすくしています。

## ライブ壁紙 {#live}

- **オーロラ**と**雨**は GPU のシェーダで描きます。内部の解像度は画面の半分(`scale 0.5`)で、ぼかしと同じ FBO を使い回します。
- AC 電源のときは 30fps、バッテリーのときは 12fps・解像度 3/4 に自動で下げます。`animate off` にすると完全に止まり、待機時の CPU はほぼ 0 になります。
- **動画の壁紙**は libmpv の描画 API で、復号した画像を**GPU 上で直接**テクスチャに描きます(CPU にコピーしません)。libmpv が使えない環境では、ffmpeg のプロセスで VA-API の復号と縮小を行い、RGBA をパイプで受け取ります。

## 1 プロセス・1 コンテキスト {#one}

バー・ドロワー・ランチャー・通知・OSD・ロック画面・壁紙は、それぞれ別の Wayland サーフェスです。ただし描画は**1 つの EGL コンテキスト**で行い、グリフアトラスやぼけた壁紙を**全部の部品で共有**します。部品ごとに別のプロセスやツールキットを立ち上げる構成と比べて、メモリも GPU のテクスチャも 1 回分で済みます。
