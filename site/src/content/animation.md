# アニメーション

ame-shell の動きは、**同じ 1 つのばね(スプリング)の物理**で計算しています。窓の開閉、パネルの出入り、通知、歌詞、トーンアーム、壁紙の切り替えの演出まで、すべてです。唯一の例外は**配色の移り変わり**で、これはわざと時間で決めています(理由は[ガラス・壁紙・配色](#/tech-glass)で説明します)。

その中核は [Odin](https://odin-lang.org/) で書いた 192 行のコード(`anim/anim.odin`)です。ネイティブでは Zig の本体に C ABI でリンクし、同じソースを WebAssembly にもビルドできます。**下のデモは、そのコードをこのページ用に WebAssembly にした本物**です(約 2 KB)。

## ばね と ベジェ曲線の違い {#spring}

多くの環境(CSS のトランジション、Hyprland の `animation`・`bezier` の設定など)は、**時間と曲線**で動きを決めます。「0.4 秒かけて、この曲線で A から B へ」という指定です。決まった動きを 1 回だけ再生するならきれいですが、**動いている途中で行き先が変わる**と、そこからもう一度「0 秒目」から始め直すことになります。そのため速度がいきなり 0 に戻ったり、跳ね上がったりします。

ばねは**今の位置と今の速度**から、次の瞬間を計算します。途中で目標が変わっても、位置と速度はそのまま引き継ぐので、**勢いを保ったまま新しい目標へ曲がっていきます**。人がものを動かすときと同じで、これが「気持ちいい」と感じる理由です。

::demo spring

> 上の帯を何度かすばやくクリックしてみてください。下のグラフは速度です。ばね(上)は速度の線がつながったまま曲がり、ベジェ(下)はクリックのたびに線が折れて、速度が飛びます。「連打」を押すと、0.18 秒ごとに行き先を変え続けます。

## ばねの式 {#math}

1 つのばねは 5 つの数だけでできています。

```odin
Spring :: struct {
	x:        f32, // 今の値
	v:        f32, // 今の速度(単位/秒)
	target:   f32, // 目標
	response: f32, // 応答時間(秒)。≒ 1 周期の長さ。小さいほど速い
	damping:  f32, // 減衰比 ζ。1 = 行き過ぎない、1 未満 = 弾む
}
```

毎フレーム、前のフレームからの経過時間 `dt` だけ進めます。応答時間と減衰比から、ばね定数 `k = (2π / response)²` と減衰係数 `c = 4πζ / response` を求めます。そして半陰的オイラー法で `v += (-k(x - target) - c·v)·h`、`x += v·h` と積分します。刻み `h` は最大 1 ミリ秒に分割します。こうすると、120Hz の画面でも 30Hz に落ちても、**同じ見た目の動き**になります(フレームレートに依存しない)。

- **「応答時間」と「減衰比」の 2 つだけ**で動きを決めます。物理の質量や剛性を考える必要はありません。iOS / SwiftUI の `response` / `dampingFraction` と同じ考え方です。
- 止まったかどうかは「ずれ 0.005 px 未満・速度 0.01 px/s 未満」で判定します。止まったら描画をやめるので、**動いていない間の負荷は 0** です。
- 計算は四則演算だけで書いていて、ライブラリ(libm)も使いません。そのため、ネイティブ(musl / glibc / FreeBSD libc)と wasm32 のどれでも、同じコードが同じ結果を出します。

## 窓のアニメーション {#windows}

River 0.5 のセッションでは、ame-shell が [river-window-management-v1](https://codeberg.org/river/river) でウィンドウマネージャを兼ねます。配置は Hyprland の dwindle と同じ考え方で、「残りの領域を長い辺で 2 分割」していきます。

::video windows | 窓が開く・並び替わる・入れ替わる・閉じる。全部ばねで動きます(録画: River 0.5 の入れ子のセッション)

| 動き | 使うばね | 中身 |
|---|---|---|
| 開く | `reveal`(応答 0.30 秒・減衰 0.68) | 中心から広がる。少しだけ行き過ぎて戻る |
| 位置・大きさの変化 | `px` `py`(0.36・0.80)、`cw` `ch`(0.30・0.90) | 新しい窓が入ると、ほかの窓が滑らかに場所を空ける |
| ワークスペースの切り替え | `slide`(0.42・0.92) | 右のワークスペースへ移ると、今の窓は左へ出て、新しい窓は右から入る |
| 閉じる(Super+Q) | `reveal` を 0 へ | 中心へ縮みきってから、アプリに閉じる要求を送る。保存確認などで閉じなかったら元に戻る |

- **アニメーション中だけ** River に「配置を更新して」と頼みます。何も動いていなければ River とのやりとりは発生しません。
- 窓を閉じる途中に別の窓を開くなど、**動きが重なっても**ばねなので破綻しません。

## シェルの動き {#shell}

| 部品 | 動き |
|---|---|
| ダッシュボード・通知センター・ランチャー | 画面の縁の「枠」からドロワーとして伸びる。開きながら閉じても、途中から自然に戻る |
| タブの切り替え | 下線と中身がばねで横に滑る |
| 通知 | 右から滑り込み、上が消えると下のカードがばねで詰める。消えるときは右へ流れて薄くなる |
| OSD(音量・明るさ) | 下からポップ(位置・拡大・不透明度を 1 つのばねで) |
| 同期歌詞 | 行が変わるたびに下からポンと弾んで出て、前の行は上へ消える |
| トーンアーム | 再生すると針が溝へ降り、曲の進みに合わせて内側へ。止めると持ち上がって外へ |
| 配色 | 壁紙やアルバムアートが変わると、アクセント・ガラス・文字色が 1.1 秒かけて移り変わる(ここだけは時間ベース。どのサーフェスが何回描いても同じ色にするため) |
| 壁紙の切り替え | 選んだカードの位置から、波紋・円・斜めワイプ・短冊のどれかで広がる |
| 速さ | 設定の `theme { anim-speed 1.0 }` で全体の速さを一度に変えられる |

## 描画のタイミング {#frames}

ame-shell は、アニメーションのために「16 ms ごとに起きる」ようなタイマーを使いません。

1. 状態が変わったら、そのサーフェスだけ `wl_surface.frame`(次の画面更新の合図)を頼む
2. コンポジタから合図が来たら、前回からの経過時間でばねを進めて描く
3. まだ動いていれば次の合図を頼み、止まっていれば何もしない

画面が見えていないときや、何も動いていないときは CPU も GPU も使いません。`eglSwapInterval(0)` にして同期はフレームコールバックで取っているので、複数のサーフェスがお互いの垂直同期を待ってカクつくこともありません。
