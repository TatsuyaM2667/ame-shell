# 名前を SeoritsuOS に。窓は波紋で開き、フォーカスはカーソルの下へ

今回は、使っていて気になっていた所を 4 つ直しました。ウィンドウマネージャの並べ方、窓が開くときの動き、フォーカス、アプリの入れ方です。名前も ame-shell から **SeoritsuOS** に変えました。

## 名前 {#name}

ログイン画面のセッション、通知、このサイトの表示は SeoritsuOS になります。リポジトリも [SeoritsuOS](https://github.com/TatsuyaM2667/SeoritsuOS) に変えました(古い URL は GitHub が転送します)。コマンド名(`ame-shell`・`ame-ctl`・`ame-*` の道具)はそのままです。変えると、すでに入れてある PC や、インストーラ・`ame-update` が動かなくなるからです。

## 左半分に窓を 2 つ並べられなかった {#dwindle}

前の並べ方は「並び順の先頭から、残りの場所を長い辺で半分に分けていく」でした。1 つ目の窓は、いつも左半分を占めます。左半分に窓を 2 つ並べたくても、できませんでした。

Hyprland の dwindle は違います。ワークスペースごとに**分け目の木**を持ち、窓を開くと、狙った窓(カーソルの下の窓)の場所だけを 2 つに分けます。左半分の窓の上で開けば、左半分が分かれます。SeoritsuOS も、この木を持つようにしました(`src/lib/dwindle.zig`)。窓は id で表すだけなので、画面が無くても `zig build test` で並び方を試せます。

```zig
try tr.insert(1, null, false);
try tr.insert(2, 1, false);   // 1 | 2
try tr.insert(3, 1, false);   // 1 の場所(正方形)を上下に → 左半分に 1 と 3
```

Hyprland と同じく、Super+矢印でその向きの窓へフォーカス、Super+Shift+矢印で入れ替え、Super+Ctrl+J で分け目の向きを逆にできます。Super+右ドラッグは、窓を浮かせずに分け目を動かします。

## 新しい窓は、カーソルの反対側に {#focus}

もう 1 つの要望は「フォーカスは常にカーソルの下の窓に。新しく開いた窓が勝手にフォーカスを取るのは不便」でした。

ところが Hyprland のように、新しい窓を**カーソルのある側**に入れると、新しい窓がちょうどカーソルの下に来ます。「フォーカスはカーソルの下」の決まりに従うと、結局新しい窓がフォーカスを取ってしまいます。

そこで、新しい窓は**カーソルの反対側**に入れることにしました。カーソルは元の窓の上に残るので、フォーカスもそのままです。2 つの要望が、1 つの規則で両方守れます。保存の確認のようなダイアログだけは、開いたときにフォーカスします。

## 窓は水の波紋で開く {#ripple}

窓が開く動きは「中心から広がる」でしたが、角ばっていて速すぎました。そこで、ロック解除の水の波紋を、窓の大きさで使うことにしました。

River のウィンドウマネージャは、窓の位置と切り抜きしか決められません。窓の中身に効果はかけられません。そこで、たわむ窓と同じ手を使います。開いた窓が最初に描けたら、その中身を 1 枚の絵として撮ります。本物の窓は 1 画素に切り抜いて隠しておき、オーバーレイに波紋のシェーダーで描きます。ロック解除の波紋は「波が通った所が透ける」ものなので、それを逆にして「波が通った所に窓が現れる」ようにしました。

窓を撮る部分は、たわむ動きと共通の `wincap.zig` に切り出しました。撮れないときは、前より少しゆっくり、やわらかく中心から広がります。

## kuraokami だけ入らなかった {#apps}

Arch と FreeBSD で、インストーラが毎回 kuraokami だけ入れられませんでした。kuraokami のビルドは、文字の整形の部品(kb_text_shape)を、Odin の置き場の中に作ります。Arch の odin パッケージは `/usr/lib/odin` にあり、FreeBSD の Odin は root がビルドしたものです。どちらも、一般のユーザーには書けません。

書けないときは、自分用の Odin の置き場を `~/.cache` に作るようにしました。中身はほとんど元へのリンクで、kb_text_shape だけを写します。`ODIN_ROOT` をそこへ向けてビルドします。Arch のコンテナで、kuraokami が入ることを確かめました。

`ame-update` でアプリが更新されない問題もありました。アプリは「SeoritsuOS が決めた版」に合わせていたので、SeoritsuOS 側で版を上げない限り「最新です」で終わっていたのです。今は GitHub の最新と比べ、新しければ作り直します。3 つのアプリは、新しいページ [ame のアプリ](#/apps) にまとめました。

## Fedora と NixOS {#distros}

Fedora は `install.sh` が見分けて dnf で入れます。Fedora 44 のコンテナで、最初から最後まで警告なしで通りました。NixOS は `/usr` に入れる作りではないので、flake を用意しました。`nix build github:TatsuyaM2667/SeoritsuOS` が nixos/nix のコンテナで通ります。
