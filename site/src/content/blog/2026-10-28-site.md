# このサイトを WebAssembly で作った

このサイトは、ame-shell と同じ考え方で作っています。本文を HTML にするのは **Zig で書いた WebAssembly**、デモは ame-shell 本体と**同じ Odin のコード**です([このサイトの作り](#/tech-site))。

## なぜ静的サイトジェネレータを使わないか {#why}

普通なら、Markdown を HTML に変換するツール(Hugo や Node.js のもの)を使います。でも ame-shell のルールでは Node.js も Python も使いません。そこで、**変換そのものを WebAssembly にして、ブラウザの中で行う**ことにしました。本文はビルドのときに wasm に埋め込まれ、ページを切り替えるたびに wasm が HTML を作ります。

## デモは本物 {#demo}

[アニメーション](#/animation)のページのばねのデモは、ame-shell の `anim/anim.odin` を `freestanding_wasm32` にビルドしたもの(約 2 KB)を、そのまま呼んでいます。「ame-shell のばねは途中で行き先が変わっても速度が途切れない」という主張を、**本物のコードで**確かめられます。

[配色のデモ](#/shell)も、主色は Odin の関数そのもの、アクセントは ame-shell の `theme.zig` と同じ計算です。最初はアクセントも Odin の主色から作っていると書いていましたが、技術解説を書くために実装を読み直したら違っていた(アクセントは「鮮やかな色相の分布の山」から作っていた)ので、説明もデモも直しました。

## 関数リファレンスは自動生成 {#ref}

[関数リファレンス](#/ref)は、ビルドのときに `site/gen/refgen.zig` が ame-shell のソースを読んで、すべての関数・型・定数のシグネチャと説明コメントを集めて作っています。手で書くと、ソースが変わったときにずれていきます。ソースから作れば、**必ず一致します**。

## Zig の defer の罠 {#defer}

書いていて、目次の閉じタグが落ちる不具合がありました。`defer raw("</div>")` で閉じていたのですが、Zig の `defer` は **`return` の式を評価した後に**動きます。長さを返した後に閉じタグが書かれていたので、JavaScript から見ると、閉じタグが無かったのです。
