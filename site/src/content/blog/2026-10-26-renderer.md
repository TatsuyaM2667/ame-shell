# 1 種類の四角形で全部を描く: 525 ms のフレームを 0 にするまで

ame-shell の UI は、OpenGL ES 3 で自作したレンダラで描いています。描くのは**インスタンス描画の四角形 1 種類**だけです([GPU レンダラ](#/tech-gpu))。この記事は、その設計と、初めてランチャーを開いたときに 1 フレームが 525 ms かかった問題の話です。

## なぜ四角形 1 種類か {#quad}

UI の部品は、角丸の矩形・影・ガラス・文字・円弧・線・画像です。それぞれ別のシェーダで描くと、部品が切り替わるたびに描画を区切る必要があります。

そこで、全部を「四角形 + 形の種類の番号」にし、形は**フラグメントシェーダの中の[[sdf|距離場]]**で決めることにしました。四角形 1 つは 28 個の float です。フレームの間に配列に積み、最後に `glDrawArraysInstanced` を 1 回呼ぶだけです。結果、1 回の描画の CPU 時間は平均 1 ms 前後になりました。

## 525 ms のフレーム {#spike}

ところが、`AME_DEBUG_FRAMES=8`(8 ms を超えたフレームの内訳を出す)で調べると、初めてランチャーを開いたときだけ、1 フレームが **525 ms** かかっていました。

内訳は「文字の生成」でした。ランチャーには約 100 字の新しい文字(アプリ名の漢字など)があり、FreeType の `sdf` モード(輪郭から直接距離場を作る)は、画数の多い漢字で **1 字 6.6 ms** かかっていました。

## 直し方 {#fix}

1. **作り方を変える**: いったん普通のアンチエイリアスで画像にしてから距離場に変換する `bsdf` モードにしました。1 字 **2.2 ms**。スクリーンショットを並べても、UI の大きさでは違いが分かりませんでした([[freetype]])。
2. **先に作っておく**: 起動して 400 ms 後から、よく使う文字(ASCII・かな・UI の漢字・アイコン・インストールされているアプリ名)を、**1 回 6 ms まで、12 ms おき**に作っておきます。1 回の作業を 1 フレームより短くしているので、先読み中に操作しても引っかかりません。
3. **アトラスを最初から最大に**: 文字を詰める画像([[glyph-atlas]])が足りなくなって広げるとき、全部の文字を作り直していました。最初から 2048² にしました。

結果、**ランチャーを開いたときに作る文字は 0 字**になりました。同じように、巨大なアイコン(PNG のデコードだけで 92 ms)はワーカースレッドに、ダッシュボードのアイコンのグリフ(19 ms)は先読みに入れて、すべての最初の操作が 1 フレームの予算に収まりました。

## 学んだこと {#lesson}

平均の数字(1 ms)だけを見ていたら、この問題には気づきませんでした。**最大の数字**と、遅いフレームの**内訳**を、最初から測れるようにしておいたことが効きました。
