# 道具に神々の名前を: curl も wf-recorder も swaylock もやめた

11 月 2 日に「cava も playerctl も nmcli も grim もやめた」と書きました。今回はその続きです。ame-shell が呼んでいた外のコマンドを、残らず自前の小さな道具に置き換えました。1 つの道具は 1 つのことだけをし、1 行の文字で答えます。端末からも、ame-shell からも、同じように使えます。

## 名前は神話から {#names}

ame は「雨」とも「天(あめ)」とも読めます。日本神話の神には「天之(あめの)〜」で始まる名前が多いので、`ame-` の後ろに神の名前を置くと「天の〇〇」として意味がつながります。

| 道具 | 置き換えたもの | 名前 |
|---|---|---|
| `amaterasu` | brightnessctl | 光の神、天照大神 |
| `ame-tajikara` | powerprofilesctl | 力の神、天手力男神 |
| `ame-uzume` | wpctl・`pactl subscribe` | 天岩戸の前で舞い、音を鳴らした天宇受売命 |
| `ame-hamon` | cava | 雨の波紋 |
| `ame-yatagarasu` | curl | 道案内をし、ものを運ぶ八咫烏 |
| `ame-rec` | wf-recorder | (ふつうの名前) |
| `ame-iwato` | swaylock | 天照大神がこもった天岩戸 |
| `ame-copy` / `ame-paste` | wl-copy・wl-paste | |

天照・宇受売・手力男は、どれも天岩戸の話に出てきます。ロックの道具が岩戸なのはそのためです。天気(`ame-weather`)と録画(`ame-rec`)は、わかりやすさを取ってふつうの名前のままにしました。手の認識は千手観音(`ame-senju`)、顔認証は八咫鏡(`ame-kagami`)にしました。

## 再起動で明るさと音量が戻らない {#restore}

きっかけは「再起動すると明るさと音量が保存されていない」という報告でした。

- **明るさ**: Linux は起動のたびに、明るさをファームウェアの値に戻します。Chimera Linux には、前の値に戻す仕組みがありませんでした。
- **音量**: WirePlumber はちゃんと保存していました。ただし**出力の機器ごと**です。スピーカーには昔の「消音・0.6%」が残っていて、イヤホンがつながっていない起動ではそれが戻っていました。

そこで `amaterasu`・`ame-uzume`・`ame-tajikara` は、自分で set した値を `~/.local/state/ame-shell/` に覚え、ログインのときに `restore` で戻します。明るさの `/sys` は root しか書けないので、`amaterasu` は logind の `Session.SetBrightness` に頼みます。root も setuid も要りません。

## 音の道具は Odin で {#odin}

`ame-uzume`(音量)と `ame-hamon`(スペクトラム)は Odin で書きました。どちらも libpulse を実行時に読むので、ヘッダも -dev パッケージも要りません。

- `ame-uzume watch` は、音量が変わるたびに「45」「45 muted」の 1 行を書きます。以前は `pactl subscribe` の行が来るたびに `wpctl` をもう 1 つ起こして読み直していました。
- `ame-hamon` は ame-shell と同じ `anim/fft.odin` で FFT し、棒の高さを 1 行ずつ書きます。全部 0 の行は続けて書かないので、無音の間は ame-shell を起こしません。

ame-shell 側は、録音のスレッドが丸ごと無くなりました。`zig build` が `odin build` と `odin test` も呼びます。

## curl の代わりは、暗号だけ OpenSSL {#fetch}

`ame-yatagarasu` は、HTTP/1.1 を自分で話し、TLS と証明書の確認だけを OpenSSL に任せます。Zig 0.13 の標準の HTTP は TLS 1.3 しか話せず、1.2 だけのサイトに届きません。暗号は自分では書きません。

ame-shell の道具が使っていた curl のオプション(`-sSfL`・`-w '%{http_code}'`・`-K -`・`-G`・`--data-urlencode`…)をそのまま読み、終了コードも curl と同じ番号にしました。呼ぶ側は名前を変えるだけで済み、同じページの中身は curl と 1 バイトも違いませんでした。

最初の版は歌詞が 1 つも取れませんでした。歌詞の道具が `-G` と `--data-urlencode` を使っていたのを、見落としていたためです。

## 録画は 3 回まちがえた {#rec}

`ame-rec` は、画面を ext-image-copy-capture で**変わったときだけ**撮り、生の画素を ffmpeg に流します。変換は GPU(VAAPI)を先に試します。ここは 3 回まちがえました。

1. **止めても終わらない**: 画素の入力を閉じても、音の入力が続くので ffmpeg が終わりませんでした。5 秒録るつもりが 125 秒のファイルになりました。→ 入力を閉じてから SIGINT を送る。
2. **5 秒が 2.5 秒になる**: `-fps_mode vfr` だと、届いた時刻が無視されて 25 コマ/秒に並べ直されていました。→ `passthrough` にして、届いた時刻のまま書く。
3. **それでも 1.7 秒**: 画面が止まっている間はコマが来ないので、動画は最後に変わった所で終わります。そこへ `-shortest` が音まで切っていました。→ `-shortest` をやめ、止まった画面でも 1 秒ごとに同じコマを送る。

直した後は、5 秒録って動画 4.92 秒・音 5.05 秒です。

## 岩戸 {#iwato}

`ame-iwato` は、どのコンポジタでも動く単体のロック画面です。雨の夜の色の上に入力の輪だけを出し、文字は使いません。ame-shell の中のロック画面(顔認証・曲のカード)はそのまま残しました。ame-shell が落ちてロックが残ったときは、別の端末から `ame-iwato` で外せます。

試験では、正しいパスワードを打っても外れないことがありました。原因は道具ではなく、試験用の仮想キーボードでした。仮想キーボードは起動したときに作られるので、最初の 1 文字がキーボードの準備より先に届いて捨てられていたのです。打っていたのは `ame` ではなく `me` で、道具は正しく「違う」と答えていました。

## 切り出し {#split}

道具はそれぞれ、単独でビルドできるリポジトリにもしました。正本は ame-shell で、`scripts/split-repos.sh` が生成します。Odin の道具は `build.sh` と `odin test`、Wayland の道具はプロトコルの XML を持ち、ビルドで wayland-scanner を通します。一覧は[小さな道具](#/tech-tools)のページにあります。

古い名前(ame-light・ame-vol など)は、しばらく新しい名前へのリンクとして入ります。
