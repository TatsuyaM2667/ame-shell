# cava も playerctl も nmcli も grim もやめた

ame-shell は最初、外のコマンドをたくさん呼んでいました。音のスペクトラムは cava、再生中の曲は playerctl、Wi-Fi は nmcli、Bluetooth は bluetoothctl、スクリーンショットは grim・slurp・wl-copy。動かすだけならこれがいちばん早いのですが、使い込むうちに困ることが増えたので、11 月の頭にまとめて ame-shell の中へ取り込みました。

## 外のコマンドで困ったこと {#why}

| 困ったこと | 例 |
|---|---|
| **押すたびに起動の時間がかかる** | nmcli は 1 回 30〜100 ms。bluetoothctl はデーモン待ちで数秒止まることもある |
| **出力の形が変わる・壊れる** | pactl の JSON は、日本語の機器名(AirPods の名前など)で壊れる |
| **入っていないと黙って失敗する** | grim が無いとスクショが撮れないのに、何も言わない |
| **常駐プロセスが増える** | `playerctl --follow`・cava が、ame-shell の横でずっと動いている |
| **再起動のたびに残る** | ame-shell を読み込み直すと、古い playerctl や pactl が残っていた |

## 何に置き換えたか {#what}

| 以前 | 今 | ファイル |
|---|---|---|
| cava | 再生中の音を libpulse-simple(dlopen)で 1/60 秒ずつ録音し、Odin の FFT で 48 帯に分ける | `src/frame/data.zig` の `Spectrum`・`anim/fft.odin` |
| playerctl | MPRIS を D-Bus(libdbus)で直接聞く。シーク(`Seeked`)も届く | `src/media/mpris.zig` |
| nmcli・bluetoothctl | NetworkManager と BlueZ をシステムバスで直接。時間のかかる呼び出しはワーカースレッドで | `src/platform/netdbus.zig` |
| grim・slurp・wl-copy | `ext-image-copy-capture` で撮り、止めた画面の上でドラッグして範囲を選び、PNG は自前のエンコーダ、クリップボードは `ext-data-control` | `src/desktop/shot.zig` |

nmcli から乗り換えるとき、**結果の文字列は nmcli の出力と同じ形**にしました。パネルの側(`netpanel.zig`)の解釈をそのまま使えるので、置き換えで壊れる場所が「D-Bus を呼ぶところ」だけに絞られます。

## 描画を止めないこと {#nonblocking}

全部を中に入れて気づいたのは、**描画の途中で返事を待つ呼び出し**が紛れ込みやすいことです。点検で 3 つ見つけて直しました。

- **Wi-Fi の名前**: バーに出す SSID を、周りのアクセスポイントを全部列挙して探していた → 無線の機器ごとの `ActiveAccessPoint` を 1 つ読むだけに
- **サイドバーの Wi-Fi / Bluetooth の切り替え**: D-Bus の返事をその場で待っていた → ワーカーで呼び、見た目は先に切り替える
- **曲の再生位置**: 3 秒ごとに MPRIS の `Position` を同期で問い合わせていた → 送るだけにして、返事が届いたときに位置を直す

コマンドを呼んでいたころは「子プロセスの出力を pipe で待つ」形だったので、自然と非同期でした。自分で D-Bus を呼ぶようになって、かえって同期の呼び出しが入り込んだわけです。

## 録画に音が入っていなかった {#record}

録画だけは今も wf-recorder を使っています。ところが「音楽を流しながら録画したのに、まったく音が入っていない」と言われました。音の指定をしていなかったのです。

`-a` を付けるだけだと、既定の**入力**(マイク)を録ります。PC で鳴っている音を録るには出力の「モニター」を指定しますが、ここにも落とし穴がありました。

- PulseAudio では `<出力の名前>.monitor` を指定する
- PipeWire(wf-recorder の pipewire の経路)では、その名前が見つからず、**黙ってマイクに切り替わる**。出力の名前をそのまま渡すと、その出力の音が録れる

そこで `pactl info` で PipeWire かどうかを見て、渡し方を変えています。もう一つの原因は単純で、直した版がインストールされていませんでした。動いていたのは `/usr/local/bin` の古い ame-shell で、ビルドしただけの `zig-out/` は使われていなかったのです。
