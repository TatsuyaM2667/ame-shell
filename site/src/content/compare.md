# ほかの WM・デスクトップと比較

ame-shell は「シェル(バー・ランチャー・通知・ロック・壁紙・ダッシュボード)」と「ウィンドウマネージャ」を**1 つのプログラム**にしたものです。ほかの環境はたいてい、コンポジタに別々のプログラムを組み合わせて作ります。ここでは、それぞれの**作りの違い**を比べます。

> 性能の数字は、同じ機械・同じ条件で測ったものしか比べられないので、ここには載せていません。ame-shell の実測は[性能](#/performance)のページにあります。各ソフトの情報は 2026 年 10 月時点のものです(FreeBSD のパッケージは FreeBSD 15 の quarterly で確認)。

## Hyprland と比べて {#hyprland}

Hyprland は、アニメーションと見た目で人気のタイリング型コンポジタです。ame-shell の窓の配置(dwindle)や「新しい窓はフォーカス中の窓の次に入る」動きは、Hyprland と同じ考え方にしています。

**ame-shell のほうが優れているところ**

- **動きの質**: Hyprland は `bezier = myBezier, 0.05, 0.9, 0.1, 1.05` のような曲線と時間で動かします。ame-shell は**ばね**なので、連打や開閉の重なりで行き先が変わっても**速度がつながったまま**です([デモ](#/animation))。
- **全部がそろう**: Hyprland でデスクトップを作るには、バー(waybar)・ランチャー(rofi / wofi)・通知(mako / swaync)・ロック(hyprlock)・壁紙(hyprpaper / swww)などを別々に選んで設定し、見た目を合わせる必要があります。ame-shell は最初から全部入りで、**同じガラス・同じ配色・同じばね**で動きます。
- **壁紙から配色**: 壁紙(動画でも)とアルバムアートから配色を作り、すべての部品の色がなめらかに移り変わります。
- **起動が速く、待機中は眠る**: 部品ごとにプロセスを立ち上げないので、ログインしてから約 0.1 秒でバーが出ます。

**Hyprland のほうが優れているところ**

- **窓越しのぼかし**・窓の角丸・影など、窓そのものの見た目の効果。ame-shell の WM は River に配置を頼む形なので、窓の描画には手を出せません。
- 長い実績、大きなコミュニティ、プラグイン、複数のモニタでの安定性。
- master など、ほかのレイアウト。

## niri と比べて {#niri}

niri は、窓が横に無限に並んでスクロールする独特のタイリングで、アニメーションにはばねも選べます。ame-shell との大きな違いは**シェルを含むかどうか**です。niri はコンポジタなので、バーや通知は waybar などを組み合わせます。そのため、niri のばねは窓の動きには使われますが、バーや通知の動きは各ソフトしだいです。ame-shell は**窓・パネル・通知・歌詞・壁紙の切り替えまで同じばね**で動きます。

## Sway・River と比べて {#sway}

Sway と River(単体)は、軽くて安定した「道具としての」タイリング型コンポジタです。アニメーションはありません(River 0.5 自身も、窓を動かすのはウィンドウマネージャの役目)。ame-shell は River 0.5 を土台にして、**その上に WM とシェルを載せたもの**と言えます。River の軽さはそのままに、アニメーションと UI を足しています。

## GNOME・KDE Plasma と比べて {#de}

GNOME と KDE Plasma は、設定アプリ・ファイルマネージャ・多数のアプリまでそろった**デスクトップ環境**です。ame-shell は**シェルと WM だけ**で、アプリは好きなものを使います。

- **作り**: GNOME Shell は JavaScript(GJS)と Clutter、Plasma は Qt / QML で UI を書いています。ame-shell は**ツールキットを使わず**、Zig から GPU に直接描きます。
- **得意なこと**: ame-shell はタイリング・キーボード中心の操作・軽さ・アニメーション。GNOME / Plasma は、設定画面の充実、アクセシビリティ、IME、トレイ、複数モニタ、長年の安定性。

## Quickshell 系のシェル(caelestia など)と比べて {#quickshell}

ame-shell の見た目(画面の縁の枠と、そこから伸びるドロワー)は、[caelestia](https://github.com/caelestia-dots/shell) の考え方を参考にしています。caelestia などは [Quickshell](https://quickshell.org/)(Qt 6 の QML でシェルを書く仕組み)の上で作られていて、WM には主に Hyprland を使います。

- ame-shell は同じような UI を **Qt を使わずに** Zig で書き直し、**WM も同じプロセス**に入れています。
- QML はとても柔軟で、作り替えが簡単です。一方 ame-shell は、UI を変えるには Zig のコードを書くか、**WebAssembly のウィジェット**を書きます。

## ame-shell の弱点 {#weak}

正直に書いておきます。

- 一人で作っている**若いプロジェクト**です。複数モニタの検証はまだ少ないです。
- **窓越しのぼかし**はできません(River にその仕組みがないため)。
- ランチャーでの**日本語入力(IME)**と、**システムトレイ**は未対応です。
- 窓のアニメーションは **River 0.5 のセッション**だけです(River 0.3 では使えません)。
- UI の文字は今のところ**日本語だけ**です。

## どれを選ぶ? {#choose}

| こんな人に | おすすめ |
|---|---|
| 窓もパネルも全部「気持ちいい動き」でそろえたい。全部入りで、組み合わせる手間をかけたくない | **ame-shell** |
| 窓の見た目の効果(窓越しのぼかしなど)やプラグインを細かく作り込みたい | Hyprland |
| 横にスクロールする新しいタイリングを使いたい | niri |
| アニメーションは要らず、とにかく安定・軽量 | Sway / River |
| 設定画面やアプリまでそろった環境がいい | GNOME / KDE Plasma |
| QML で自分のシェルを自由に作りたい | Quickshell |
| FreeBSD で、タイリングとアニメーションのある環境を簡単に作りたい | **ame-shell**(自動インストーラ付き) |
