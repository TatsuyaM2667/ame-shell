# あいまい検索

::infobox あいまい検索
英語 | Fuzzy matching
例 | fzf、VS Code の Ctrl+P、ランチャー
考え方 | 入力の文字が、順番どおりに(飛び飛びでも)現れれば一致
ame-shell | ランチャー(Odin の ame_fuzzy_score)

**あいまい検索**は、入力が名前の中に**順番どおりに現れれば**、飛び飛びでも一致とみなし、「それらしさ」の点数で並べる検索です。

## 概要 {#overview}

「vsc」と打って「Visual Studio Code」を見つけたい、ということがあります。普通の検索(含まれているか)では見つかりませんが、あいまい検索では、v・s・c が順に現れるので一致します。さらに、単語の先頭で一致したもの(V-isual S-tudio C-ode)を高く評価すれば、いちばん欲しいものが上に来ます。

## 仕組み {#how}

ame-shell の方法(Odin の `ame_fuzzy_score`):

1. 名前を前から 1 文字ずつ見て、入力の次の文字と一致したら進む(貪欲)。
2. 一致した文字に点を付ける: 基本 +10、文字列の先頭 +30、区切り(空白 `-` `_` `.` `/`)の直後 +20、camelCase の境目 +15、直前も一致(連続)+18、前の一致からの飛びの分だけ減点。
3. 入力を全部使い切れなかったら不一致(−1)。
4. 最初の一致が遅いほど、名前が長いほど、少し減点。

## ame-shell での使われ方 {#ame}

ランチャーは、アプリの名前・日本語名・一般名・キーワード・コマンド名のそれぞれに掛け、いちばん良い点を使います。さらに [[frecency]] を足して並べます([ランチャー](#/tech-launcher))。[デモ](#/shell)で試せます。

## 理論と研究 {#theory}

:::research 部分列一致と、最適な整列
「入力が名前の部分列か」は、前から貪欲になめるだけで O(n) で判定できます。ただ、**点数が最大になる一致の仕方**を求めるには、どの文字に対応させるかを選ぶ必要があり、動的計画法(Smith–Waterman の局所整列に似た O(nm) の計算)になります。fzf の v2 のアルゴリズムはこの方式です。

ame-shell の方式は貪欲(最初に見つかった文字に対応させる)なので、点数は最適とは限りません。例えば「ab」に対して「a-x-a-b」では、最初の a に対応させるため、連続一致(2 つ目の a と b)を取り逃します。ランチャーのアプリ名は短く、この差がほとんど問題にならないので、速さ(O(n)、メモリの確保なし)を優先しています。
:::
