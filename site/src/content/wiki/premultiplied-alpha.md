# 乗算済みアルファ

::infobox 乗算済みアルファ
英語 | Premultiplied alpha
表し方 | (r·a, g·a, b·a, a)
ブレンドの式 | 結果 = 前景 + 背景 × (1 − 前景のアルファ)
提唱 | Porter & Duff(1984)

**乗算済みアルファ**は、色の値に、あらかじめ不透明度(アルファ)を掛けておく表し方です。半透明のものを重ねるときの計算が単純になり、縁が黒ずむ問題が起きません。

## 概要 {#overview}

赤くて半分透明な点を考えます。普通の表し方では「赤 = 1、不透明度 = 0.5」。乗算済みでは「赤 = 0.5(= 1 × 0.5)、不透明度 = 0.5」と書きます。

違いが出るのは、**拡大や縮小で隣のピクセルと混ざるとき**です。普通の表し方だと、透明なピクセル(色は黒、不透明度 0)と混ざったときに黒が混ざり、縁が暗くにじみます。乗算済みなら、透明なピクセルは「色も 0」なので、混ぜても色が濁りません。

## 仕組み {#how}

前景 `F`(乗算済み)を背景 `B` に重ねる「over」演算は、

```
結果.rgb = F.rgb + B.rgb × (1 − F.a)
結果.a   = F.a   + B.a   × (1 − F.a)
```

OpenGL では `glBlendFunc(GL_ONE, GL_ONE_MINUS_SRC_ALPHA)` です。色とアルファが**同じ式**になるのがポイントです。

## ame-shell での使われ方 {#ame}

ame-shell のシェーダは、最後に必ず `pm(c) = vec4(c.rgb × c.a, c.a)` で乗算済みに直してから出力します([GPU レンダラ](#/tech-gpu))。

- 影(色付きの半透明)と、発光(ほぼ足し算)を同じブレンドの式で描ける。
- [[wayland|Wayland]] のコンポジタは、サーフェスの中身を乗算済みとして合成するので、そのまま渡せる。

## 理論と研究 {#theory}

:::research Porter–Duff の合成代数
Porter と Duff(1984)は、各ピクセルを「被覆率 α で色 C の小片が覆っている」とみなし、2 つの画像の重ね方(over・in・out・atop・xor…)を、被覆の確率の掛け算として体系化しました。乗算済みの表現 `(αC, α)` では、すべての演算が `結果 = F·Fa + B·Fb`(Fa・Fb は 0・1・α・1−α のいずれか)という**線形の式**で書けます。

線形であることの利点は、**フィルタリング(補間・ぼかし)と合成が交換できる**ことです。乗算済みでない表現で線形補間すると、`(C1·α1 + C2·α2)/(α1 + α2)` のような割り算が必要になり、α → 0 で不安定になります。テクスチャのミップマップやぼかしを正しく行うには、乗算済みで計算する必要があります(Blinn, "Compositing, Part 1: Theory", 1994)。
:::
