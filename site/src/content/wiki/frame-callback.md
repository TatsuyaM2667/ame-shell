# フレームコールバック

::infobox wl_surface.frame
種類 | Wayland のリクエストとイベント
意味 | 「次に描くのにちょうどいい時」の合図
ame-shell | すべての描画のきっかけ

**フレームコールバック**(`wl_surface.frame`)は、アプリが [[compositor|コンポジタ]] に「次の絵を描くのにちょうどいい時に教えて」と頼み、コンポジタが合図(`done`)を返す仕組みです。

## 概要 {#overview}

アニメーションを滑らかに見せるには、画面の更新(1 秒に 60 回や 120 回)に合わせて絵を描く必要があります。早すぎると描いた絵が捨てられ、遅すぎるとカクつきます。フレームコールバックは、コンポジタが「今描けば次の更新に間に合うよ」と教えてくれる仕組みです。

もう 1 つ大事な性質は、**窓が見えていないときは合図が来ない**ことです。隠れている窓は描かなくて済むので、電池の節約になります。

## 仕組み {#how}

```
アプリ:   wl_surface.frame() → callback を作る → wl_surface.commit()
コンポジタ: (画面に出した後)callback.done(時刻) を送る
アプリ:   done を受けたら、時刻の差で動きを進めて描く → 動いていれば次の frame を頼む
```

`done` には時刻(ミリ秒)が付いています。前回の時刻との差を経過時間 `dt` として使うと、画面のリフレッシュレートが違っても同じ速さで動きます。

## ame-shell での使われ方 {#ame}

ame-shell の描画は**すべてこの合図から始まります**。状態が変わったサーフェスだけが合図を頼み、[[spring|ばね]]が止まったら次を頼みません。そのため何も動いていないときは CPU も GPU も使いません([Wayland とサーフェス](#/tech-wayland))。複数のサーフェスが互いを待たないよう、`eglSwapInterval(0)` と組み合わせています([[vsync]])。

## 理論と研究 {#theory}

フレームコールバックは「描くタイミング」を教えますが、「実際に画面に出た時刻」は教えません。より正確な時刻(画面に出た瞬間と次の更新の予定)が必要な動画プレーヤーなどは、`wp_presentation`(presentation-time)を使います。アニメーションの位置を「表示される予定の時刻」で計算すると、入力から表示までの遅延の揺れ(ジッタ)が減ります。
