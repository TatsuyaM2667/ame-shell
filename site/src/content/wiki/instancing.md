# インスタンス描画

::infobox インスタンス描画
英語 | Instanced rendering
API | glDrawArraysInstanced / glDrawElementsInstanced
利点 | 同じ形をたくさん、1 回の命令で描く

**インスタンス描画**は、同じ形(例: 四角形)を、位置や色だけ変えて、**1 回の描画命令でたくさん**描く方法です。

## 概要 {#overview}

UI には、ボタン・影・文字の 1 字 1 字など、四角形が何千個もあります。1 個ずつ「描いて」と GPU に頼むと、頼む手間(CPU と GPU の間のやりとり)がかさみます。インスタンス描画では、「この四角形を、この 3000 個の値で描いて」と 1 回で頼めます。

## 仕組み {#how}

- 形(四角形の 4 つの角)は 1 つだけ用意する。
- 個ごとに違う値(位置・大きさ・色・種類…)を配列にして GPU に送る。
- `glVertexAttribDivisor(位置, 1)` で、その値が「頂点ごと」ではなく「1 個(インスタンス)ごと」に進むようにする。
- `glDrawArraysInstanced(GL_TRIANGLE_STRIP, 0, 4, 個数)` で描く。

## ame-shell での使われ方 {#ame}

ame-shell の UI はすべて、この方法で描いています。1 つの四角形は **28 個の float**(位置・3 つの色・形の種類と角丸・UV・クリップの矩形)で、フレームの間に配列に積んでいき、最後に 1 回で描きます。区切りが入るのは、使う画像(アルバムアートとアイコンなど)が変わるときだけです([GPU レンダラ](#/tech-gpu))。

## 理論と研究 {#theory}

:::research どこが速くなるか
描画のコストは、おおまかに「命令を出すコスト(CPU 側、ドライバの検証)× 命令の数」と「頂点・ピクセルの処理(GPU 側)」に分かれます。小さな四角形を大量に描く 2D の UI では前者が支配的なので、命令の数を減らす効果が大きく出ます。

ame-shell の方式では、形の違いをシェーダの分岐で表すので、GPU 側では「全部の四角形が同じ大きなシェーダを通る」代償があります。ただ、同じ四角形の中のピクセルは同じ分岐を通るため、GPU の SIMD の効率はほとんど落ちません。
:::
