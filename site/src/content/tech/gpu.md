# GPU レンダラ

<p class="file">対象: src/gfx.zig(1181 行)</p>

ame-shell の UI は、すべて **OpenGL ES 3 で自作した 2D レンダラ**で描いています。描くものは**1 種類の四角形**だけです。形の違い(角丸・影・ガラス・文字・円弧・線・画像・斜めのカード)は、フラグメントシェーダの中で距離場(SDF)を使って作ります。

```zig
// src/gfx.zig(冒頭)
// 設計:
//  * EGLContext は1つだけ作り、全サーフェス(バー、壁紙、ランチャー…)で共有する。
//    グリフアトラス・壁紙のブラー済みテクスチャをそのまま全パネルで使えるため。
//  * UI は「インスタンス化した四角形」1種類だけを描く。形状(角丸矩形・影・ガラス・
//    SDF文字・円弧・画像)はフラグメントシェーダ内の SDF で決めるので、1フレームの
//    描画がほぼ1回のドローコールで済む。
```

## なぜ GLES3 か {#api}

| 候補 | 判断 |
|---|---|
| **OpenGL ES 3(EGL)** | ✓ 採用。Mesa の radeonsi で GLES 3.2 が使える。2D の UI には十分で、Wayland の EGL(`wl_egl_window`)と直接つながる |
| Vulkan | コードの量が数倍になる。利点(マルチスレッドでの命令の記録など)は、この規模の UI では効かない |
| ソフトウェア描画 + `wl_shm` | ガラスのぼかしや屈折の計算が CPU に乗る |
| cairo / Skia などの 2D ライブラリ | 依存が大きい。ガラスの屈折や枠の融合のような独自の効果は、結局シェーダを書くことになる |

## 四角形 1 つ = 28 個の float {#instance}

```zig
fn push(self: *Canvas, x: f32, y: f32, w: f32, h: f32, c0: Color, c1: Color, c2: Color, p0: [4]f32, p1: [4]f32) void {
    const s = self.xf.s;
    const a = self.xf.a;
    if (a <= 0.001) return;                       // 見えないものは積まない
    const v = [INST_FLOATS]f32{
        self.xf.tx + x * s, self.xf.ty + y * s, w * s,        h * s,          // 位置と大きさ
        c0.r,               c0.g,               c0.b,         c0.a * a,       // 色 0
        c1.r,               c1.g,               c1.b,         c1.a * a,       // 色 1
        c2.r,               c2.g,               c2.b,         c2.a * a,       // 色 2
        p0[0] * s,          p0[1],              p0[2],        p0[3] * s,      // 角丸・種類・縁・ぼかし
        p1[0],              p1[1],              p1[2],        p1[3],          // UV や形ごとの値
        self.clip[0],       self.clip[1],       self.clip[2], self.clip[3],   // クリップ矩形
    };
    self.inst.appendSlice(&v) catch {};
}
```

- 1 つの四角形は **28 個の float(112 バイト)**。頂点シェーダが、単位四角形の 4 隅(`a_corner`)をこの値で広げます。
- `p0[1]` が**形の種類**です(0 = 角丸矩形、1 = 影、2 = ガラス、3 / 7 = 文字・縦書き、4 = 円弧、8 = 線分、9 = 斜めのカード、それ以外 = 画像)。
- **変換(移動・拡大・不透明度)は CPU で値に掛けてから積みます**(`self.xf`)。パネル全体を拡大しながらフェードする、といったアニメーションでも、シェーダに行列を渡す必要がありません。
- **見えないもの(不透明度 0)は積みません**。閉じたドロワーの中身は描画命令になりません。

### 描画は(ほぼ)1 回 {#draw}

```zig
pub fn flush(self: *Canvas) void {
    const n = self.inst.items.len / INST_FLOATS;
    if (n == 0) return;
    …
    c.glBlendFunc(c.GL_ONE, c.GL_ONE_MINUS_SRC_ALPHA); // 乗算済みアルファ
    …
    c.glBufferData(c.GL_ARRAY_BUFFER, @intCast(self.inst.items.len * 4), self.inst.items.ptr, c.GL_STREAM_DRAW);
    c.glDrawArraysInstanced(c.GL_TRIANGLE_STRIP, 0, 4, @intCast(n));
    …
    self.inst.clearRetainingCapacity();
}
```

テクスチャは、グリフのアトラス(ユニット 0)・ぼけた壁紙(ユニット 1)・画像 1 枚(ユニット 2)の 3 つを同時に結び付けます。文字とガラスとパネルが混ざっていても、**同じ 1 回の命令**で描けます。区切りが入るのは「別の画像(アルバムアートとアイコンなど)に切り替わるとき」だけです(`cur_img` が変わったら `flush`)。

**結果**: 1 回の描画の CPU 時間は平均 **0.8〜1.1 ms**。ダッシュボードを全部開いた状態でも、描画命令は数回です。

### 乗算済みアルファ {#premul}

ブレンドは `ONE, ONE_MINUS_SRC_ALPHA`(乗算済みアルファ)です。シェーダは最後に `pm(c) = vec4(c.rgb * c.a, c.a)` を返します。

- 半透明のものを重ねたとき、縁に**暗いにじみ**が出ません(通常のアルファ合成では、透明な部分の色が混ざって縁が黒ずむ)。
- 影(色だけ)と発光(足し算に近い)を同じブレンドの式で描けます。
- Wayland のコンポジタは、サーフェスの中身を乗算済みアルファとして合成します。最後の出力をそのまま渡せます。

## 形は距離場(SDF)で {#sdf}

```glsl
float sdBox(vec2 p, vec2 b, float r){ r = min(r, min(b.x, b.y)); vec2 q = abs(p) - b + r;
  return length(max(q, 0.0)) + min(max(q.x, q.y), 0.0) - r; }

if (kind == 0.0) {            // 角丸矩形(縦グラデーション + 縁取り)
  float d = sdBox(v_p, v_half, r);
  float a = clamp(0.5 - d / px, 0.0, 1.0);   // px = 1 物理ピクセルの論理サイズ
  vec4 fill = mix(v_c0, v_c1, clamp(v_l01.y, 0.0, 1.0));
  …
  o = pm(fill) * a;
}
```

`sdBox` は、各ピクセルから角丸矩形の縁までの**符号付きの距離**です(内側が負)。`0.5 - d / px` で、**ちょうど 1 物理ピクセルの幅でなめらかに**縁を消します。

- **どの大きさ・どの拡大率でも輪郭がにじまない**(テクスチャを拡大しないので)。
- **角丸の半径をアニメーションできる**(値を変えるだけ)。ドロワーが伸びるときに角が変わっても、絵を作り直す必要がありません。
- **縁取り・グラデーション・影が同じ式から出る**。影は `smoothstep(-s, s * 1.6, d)` を 2 乗して、ガウスぼかしに近い柔らかい落ち方を作ります。ぼかしの処理(何回もサンプルする)は要りません。

その他の形:

| 種類 | 作り方 |
|---|---|
| 円弧(パフォーマンスの円グラフ) | 円環の距離 `abs(length(p) - R) - 太さ/2` と、`atan` で求めた角度で「どこまで塗るか」を切る |
| 線分(スペクトラム・トーンアーム) | 点と線分の距離(両端が丸いカプセル) |
| 斜めのカード(壁紙ピッカー) | 座標を `x - 傾き * y` でずらしてから `sdBox`。**画像そのものは歪めず**、平行四辺形の形でくり抜く |
| 画像 | 角丸のマスク + 回転(レコードのジャケットは `v_c1.r` の角度で UV を回す) |
| 文字 | SDF のアトラスから読んだ距離を、画面のピクセルに換算する([文字](#/tech-text)) |

## クリップ {#clip}

```glsl
if (v_clip.z > 0.0) {
  vec2 q = v_frag - v_clip.xy;
  if (q.x < 0.0 || q.y < 0.0 || q.x > v_clip.z || q.y > v_clip.w) discard;
}
```

クリップの矩形も四角形ごとの値として持ちます。`glScissor` を使うと、クリップが変わるたびに描画を区切る(flush する)必要がありますが、この方法なら区切りません。Wi-Fi の一覧のスクロール(`netpanel.zig`)や、歌詞欄・WebAssembly のウィジェットの領域(ウィジェットは `clip` 命令で自分の範囲を指定する)は、すべてこの仕組みで切り取っています。

## ほかの方法との違い {#vs}

| 方法 | ame-shell との違い |
|---|---|
| ツールキット(Qt Quick・GTK4)のシーングラフ | 汎用的で、テキスト入力やアクセシビリティまで揃う。そのぶん大きく、ガラスの屈折のような独自の効果は追加のシェーダとして足すことになる |
| 部品ごとに描画命令を出す | 描画命令の数が部品の数だけ増える。ame-shell は全部を 1 つの配列に積んで 1 回で描く |
| 角丸・影を画像(9-slice)で描く | 大きさや半径を変えるたびに画像が要る。拡大でにじむ |
