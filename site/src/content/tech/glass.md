## 「後ろの壁紙」を自分で持っている {#own}

ガラス(すりガラスのパネル)を作るには、パネルの**後ろにある絵**をぼかす必要があります。普通のアプリは、自分の後ろに何があるかを知りません(Wayland では、ほかのクライアントの画面を読むことはできません)。ame-shell は**壁紙を自分で描いている**ので、パネルの後ろの壁紙を正確に知っています。これがガラスの土台です。

```zig
// src/gfx.zig
/// 1つの出力の壁紙と、そのブラー済みテクスチャ。
pub const Backdrop = struct {
    scene: Target = .{},
    levels: [5]Target = .{ .{}, .{}, .{}, .{}, .{} },
    /// パネルがサンプルする最終ブラー
    blurred: c.GLuint = 0,
    …
};
```

1. 壁紙(シェーダ・画像・動画のコマ)を、出力ごとの FBO(`scene`)に描く。
2. その `scene` から、ぼかした画像を段階的に作る(下の dual Kawase)。
3. `scene` を画面に拡大表示する(壁紙のサーフェス)。
4. ぼけた画像(`blurred`)を、ガラスのパネルがすべて共有して読む。

**1 プロセス・1 EGL コンテキスト**なので、壁紙のサーフェスで作ったテクスチャを、枠やランチャーのサーフェスから**そのまま**読めます。プロセスが分かれていると、dmabuf でテクスチャを受け渡す仕組みが必要になります。

## dual Kawase でぼかす {#kawase}

```zig
// dual Kawase: 縮小しながらぼかし、少し拡大して戻す。段数でブラーの強さを調整。
const n = std.math.clamp(passes, 1, 4);
var src: *Target = &self.scene;
var i: usize = 0;
while (i < n) : (i += 1) {
    const dst = &self.levels[i];
    dst.ensure(@divTrunc(src.w, 2), @divTrunc(src.h, 2));
    pass(gpu.down, src, dst);
    src = dst;
}
// 1段だけ戻す(戻しすぎると解像度の割にぼけが弱くなるため)
if (n >= 2) {
    const dst = &self.levels[4];
    dst.ensure(self.levels[n - 2].w, self.levels[n - 2].h);
    pass(gpu.up, src, dst);
    src = dst;
}
self.blurred = src.tex;
```

- **縮小しながらぼかす**: 1 段ごとに縦横を半分にし、そのときに中心(重み 4)と斜めの 4 点、計 5 回読んで混ぜます(`down_fs`)。テクスチャの線形補間で、1 回の読み出しが 2×2 画素の平均になるので、少ない読み出しで広い範囲を混ぜられます。3 段で 1/8 の大きさになり、元の画像で言えば数十ピクセルの範囲をぼかしたのと同じになります。
- **戻すのは 1 段だけ**: 普通の dual Kawase は元の大きさまで戻しますが、パネルは拡大して読む(テクスチャの線形補間でさらになめらかになる)ので、1 段戻せば十分です。戻すほど計算が増え、ぼけ方はむしろ弱くなります。
- 段数は設定の `theme { blur 3 }`(1〜4)。

| ぼかし方 | 1 ピクセルあたりの読み出し | 判断 |
|---|---|---|
| **dual Kawase(縮小 3 段 + 拡大 1 段)** | 縮小 5 回・拡大 8 回。ただし縮小した小さな画像の上なので、合計でも元の画像を数回読む程度 | ✓ 採用 |
| ガウスぼかし(2 パス分離) | 半径 r に対して 2r 回。大きくぼかすほど重い | 大きなぼけに向かない |
| ボックスぼかしの繰り返し | 段差が出やすい | 品質 |

**ぼかすのは壁紙が変わったときだけ**です。画像の壁紙なら、切り替えの演出中しか作り直しません。ライブ壁紙では壁紙の fps でぼかし直しますが、ガラスのパネル(枠など)は**毎回は描き直しません**。ぼけた壁紙の微妙な変化のために、全部のパネルを毎フレーム描くのは割に合わないからです。

## ガラスのシェーダ {#glass}

```glsl
} else if (kind == 2.0) {     // ガラス
  float d = sdBox(v_p, v_half, r);
  …
  // SDF の勾配 = 縁の法線
  vec2 n = normalize(vec2(sdBox(v_p + e.xy, v_half, r) - sdBox(v_p - e.xy, v_half, r),
                          sdBox(v_p + e.yx, v_half, r) - sdBox(v_p - e.yx, v_half, r)) + 1e-5);
  float edge = 1.0 - smoothstep(0.0, rim, -d);           // 縁で1、中心で0
  float refr = v_p1.x;                                    // 屈折の強さ(px)
  vec2 off = -n * edge * edge * refr;
  vec2 sp = u_origin + v_frag + off;                      // 出力上の位置 = 真後ろ
  vec2 uv = vec2(sp.x / u_output.x, 1.0 - sp.y / u_output.y);
  // 縁でわずかに色収差を付けてガラスの厚みを出す
  vec2 ca = vec2(n.x, -n.y) * edge * 1.5 / u_output;
  vec3 bg = vec3(texture(u_blur, uv + ca).r, texture(u_blur, uv).g, texture(u_blur, uv - ca).b);
  vec3 col = mix(bg, v_c0.rgb, v_c0.a);                   // 色付け
  col += v_c1.rgb * v_c1.a * (1.0 - v_l01.y);              // 上からの柔らかい光
  …
  // 細い縁のハイライト。左上からの光源を想定し、向きで明るさを変える。
  float line = clamp(1.0 - abs(d + 0.75) / (1.1 * px + 0.35), 0.0, 1.0);
  float facing = 0.35 + 0.65 * max(0.0, dot(n, normalize(vec2(-0.55, -0.85))));
  col = mix(col, v_c2.rgb, line * facing * v_c2.a);
  // 微細なノイズ(バンディング防止と素材感)
  col += (hash(gl_FragCoord.xy) - 0.5) * 0.03;
  …
}
```

| 効果 | 作り方 | 見た目の効果 |
|---|---|---|
| 真後ろを読む | サーフェスの出力上の位置 `u_origin` + ピクセルの位置 | パネルを動かしても、後ろの壁紙がずれない(本物の透明な板のように見える) |
| **屈折** | 距離場の勾配(縁の向き)の逆へ、縁ほど強く読む位置をずらす | 縁で後ろの絵が曲がり、厚みのあるガラスに見える |
| **色収差** | R と B だけ、法線の向きに 1.5 px ずつずらす | 縁がうっすら虹色になる(レンズの性質) |
| 色付け | `mix(後ろ, 色, 濃さ)` | 読みやすさの確保(`tint-strength`) |
| 縁のハイライト | 縁から 0.75 px の細い線。左上の光源に向いた辺ほど明るい | 光が当たっている感じ |
| ノイズ | 画面のピクセルごとの乱数を ±1.5% | ぼかしたグラデーションの縞(バンディング)を消し、すりガラスの質感を出す |
| きらめき | 28 px の格子ごとに 1 点、ごく一部だけが時間で瞬く | 設定 `sparkle`(0 で無効) |

>! 窓の上に出るパネル(ランチャーなど)の後ろには、壁紙ではなく他のアプリの窓があります。窓越しにぼかすには、コンポジタが「後ろをぼかす」仕組み(`ext_background_effect_manager_v1`)を提供している必要があります。River はこれを出していないことを、`WAYLAND_DEBUG` でグローバルの一覧を実際に見て確かめました。そのため、窓の上に出るパネルは色を濃くして(`glassStrong`)読みやすくしています。

## ライブ壁紙のシェーダ {#live}

壁紙のシェーダは、全画面を覆う 1 つの三角形(`glDrawArrays(GL_TRIANGLES, 0, 3)`)を描きます。四角形 2 枚より境目が無く、頂点も少なくなります。

- **オーロラ**: fbm(複数の周波数のノイズを重ねたもの)で「カーテン」の中心線を揺らし、高い周波数の fbm で縦の光の筋を作ります。下端ははっきり、上へ長く消えていきます。色は設定の `aurora-a/b/c`。
- **雨**: 3 層の「夜の街のボケ」(セルごとの円)、3 層の雨の筋(列ごとに速さを変える)、下の 22% に水たまりの波紋。円がセルの境界をはみ出すと四角く欠けるので、「中心のずれ + 半径 < 0.5」に収めています(シェーダのコメントにある工夫)。

## 壁紙の切り替えの演出 {#transition}

切り替えは**シェーダの中で前後の壁紙を同時に描いて混ぜます**。`u_mix`(0→1)はばねで進みます。

```glsl
if (u_trans == 1) {
  // 円: 選んだカードの位置から広がる。境界は光るリングで、その内側を少し屈折させる
  vec2 o = u_origin;
  vec2 d = (uv - o) * vec2(ar, 1.0);
  float r = length(d);
  float maxr = length(vec2(max(o.x, 1.0 - o.x) * ar, max(o.y, 1.0 - o.y)));
  float front = ease(m) * (maxr + 0.08);
  float band = exp(-pow((r - front) * 18.0, 2.0));
  vec2 duv = uv - normalize(d + 1e-5) / vec2(ar, 1.0) * band * 0.03;
  vec3 a = scene(u_prev_mode, duv, u_prev, u_prev_size) * (1.0 - 0.35 * m);
  vec3 b = sceneB(duv, zoom, o);
  col = mix(a, b, smoothstep(front + 0.006, front - 0.006, r)) + band * …;
}
```

- **起点は壁紙ピッカーで選んだカードの位置**(`u_origin`)。「そのカードから新しい壁紙が広がる」ように見えます。
- **光るリング**(`band`)の部分だけ、読む位置を外向きに 3% ずらして屈折させます。
- **新しい壁紙は 10% 拡大した状態から元の大きさへ落ち着きます**(`zoom = 1 + 0.10 (1 - m)²`)。着地したような感覚が出ます。
- 種類: 0 = 波紋、1 = 円、2 = 斜めワイプ(ピッカーのカードと同じ傾き)、3 = 短冊(斜めの帯ごとに時間差で塗り替える)。
- 前の壁紙がライブ壁紙や動画でも、`scene(u_prev_mode, …)` で**動いたまま**混ざります。

## 配色: 壁紙から作る {#theme}

```zig
// src/theme.zig
pub fn schemeFromPixels(rgba: [*]const u8, w: c_int, h: c_int) Scheme {
    var work: [4096 * 4]u32 = undefined;
    const count = w * h;
    const stride = @max(1, @divTrunc(count, 60_000));     // 最大 6 万画素だけ見る
    const rgb = anim.ame_dominant_color(rgba, count, stride, &work);   // Odin
    …
    // ガラス・文字の色合いは「一番多い色」、アクセントは「一番鮮やかに目立つ色」から作る
    const hh = hsl[0];
    const s = hsl[1];
    const ah = accentHue(vividHue(rgba, count, stride) orelse hh);
    return .{
        .accent = fromHsl(ah, std.math.clamp(@max(s, 0.55) * 1.15, 0.62, 0.9), 0.72),
        .tint = fromHsl(hh, std.math.clamp(s * 0.6, 0.18, 0.45), 0.085),
        .text = fromHsl(hh, 0.40, 0.95),
        .subtext = fromHsl(hh, 0.22, 0.75),
    };
}
```

**2 つの色を別々に求めています**。

| 何に使う | 求め方 | 理由 |
|---|---|---|
| **ガラス・文字の色合い**(tint・text・subtext) | Odin の `ame_dominant_color`: RGB を各 4 bit(4096 区画)に分けたヒストグラムで、「出現数 × (0.15 + 彩度²)」が最大の区画の平均色。暗すぎ・明るすぎは減点 | 画面の大部分を占める色に合わせると、ガラスが壁紙になじむ |
| **アクセント** | Zig の `vividHue`: 色相を 36 区画に分け、「彩度² × (明るさが中くらいほど大きい重み)」で数え、隣の区画とならした山 | 面積は小さくても**目を引く色**(夕焼けの一点のオレンジなど)を拾う |

明るさを `0.72`、彩度を `0.62〜0.9` に固定して HSL から作り直すので、どんな壁紙でも**暗い背景の上で読める明るさ**のアクセントになります。

### アクセントの色相を「良い色」に寄せる {#hue}

```zig
/// 黄緑〜緑(くすみやすく、UI の「有効」表示が安っぽく見える)は避けて、近い青緑か琥珀へ逃がす。
/// 赤もエラー表示(theme.danger)と紛らわしいので使わない
pub fn accentHue(h: f32) f32 {
    const anchors = [_]f32{
        0.085, // 琥珀
        0.49,  // ティール
        0.545, // スカイ
        0.6,   // ブルー
        0.665, // ペリウィンクル
        0.74,  // バイオレット
        0.83,  // オーキッド
        0.93,  // ピンク
    };
    … いちばん近いアンカーを探す …
    // 近い「良い色相」へ 75% 寄せる(壁紙らしさは少し残す)。緑の帯からは完全に出す
    var out = h + d * 0.75;
    // 赤はエラーの色と紛らわしいので、ピンクか琥珀へ完全に寄せる
    if ((h > 0.13 and h < 0.44) or h < 0.05 or h > 0.97) out = best;
    return out - @floor(out);
}
```

**なぜこうするか**: 壁紙の色をそのまま使うと、森の写真から「くすんだ黄緑」、夕焼けから「赤」が出ます。黄緑はトグルの「オン」の色として安っぽく見え、赤は ame-shell が**エラー専用**に決めた色(`theme.danger`)と区別できなくなります。そこで、アクセントの色相を 8 つの「アクセントとして見栄えの良い色相」へ 75% 寄せ、緑と赤の帯からは完全に外します。25% は元の色相を残すので、壁紙ごとの個性は消えません。

## 配色の移り変わりは「時間」で決める {#fade}

```zig
// どちらも時間ベースで補間するので、どのサーフェスが何回描いても同じ色になり、切り替えは滑らか。
const FADE_MS: f32 = 1100;
fn progress(t0: u64) f32 {
    return std.math.clamp(@as(f32, @floatFromInt(loop.nowMs() -| t0)) / FADE_MS, 0, 1);
}
fn ease(t: f32) f32 { const u = 1 - t; return 1 - u * u * u; }
```

ame-shell の動きのほとんどは**ばね**ですが、配色だけは**時間の関数**(1.1 秒の 3 次のイーズアウト)にしています。

**理由**: 色は、枠・壁紙・ランチャー・WM の窓の枠線など**たくさんのサーフェスが別々のタイミングで読む値**です。ばねは「描くたびに `dt` だけ進める」ので、サーフェスごとに進め方がずれると、同じ瞬間に違う色が出ます。時刻から計算する関数なら、いつ・何回読んでも同じ瞬間には同じ色になります。

ばねが向いているのは「1 つの持ち主が毎フレーム進める、途中で行き先が変わる値」です。配色は「みんなが読む、行き先がめったに変わらない値」なので、時間の関数のほうが正しい選択になります。

## エラーの赤い光 {#error}

```zig
/// 何かが失敗したとき(Wi-Fi の接続失敗、パスワード違い等)。枠の縁が一瞬赤く光る
pub fn flashError(app: *App) void {
    error_t0 = loop.nowMs();
    if (app.activeFrame()) |f| f.schedule();
}
/// 赤い光の強さ(0〜1、時間とともに消える)
pub fn errorLevel() f32 {
    …
    // 速く立ち上がってゆっくり消える
    const up = std.math.clamp(t * 8, 0, 1);
    return up * (1 - t) * (1 - t);
}
```

失敗(Wi-Fi の接続失敗・パスワード違い・壁紙を再生できない・録画のツールが無い・緊急の通知)は、すべてこの 1 つの関数で知らせます。1.4 秒の間、最初の 1/8 で立ち上がり、残りで 2 次曲線で消えます。**赤はこの用途にしか使わない**(アクセントからは除外している)ので、赤く光ったら必ず何かが失敗した、と分かります。
