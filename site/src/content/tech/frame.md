## 1 枚のサーフェスに全部描く {#one-surface}

画面の縁・縦バー・8 種類のドロワーを、**出力ごとに 1 枚の全画面サーフェス**に描きます。

| 方法 | 判断 |
|---|---|
| **全画面 1 枚 + 入力領域を矩形で指定** | ✓ 採用。ドロワーと縁を 1 つの形として描ける(下の smooth-min)。サーフェスの作成・破棄が無いので、開閉で引っかからない |
| ドロワーごとに別のサーフェス | 縁とドロワーの継ぎ目に段差が出る。開くたびにサーフェスを作り、コンポジタの configure を待つ遅延がある |

全画面のサーフェスでも、**入力領域**をバー・縁・今見えているドロワーの矩形だけにします。それ以外の場所のクリックは、下の窓へそのまま届きます(`setInputRects`)。

## 縁とドロワーを 1 つの形に溶かす(smooth-min) {#smin}

```glsl
float smin(float a, float b, float k){ if (k <= 0.01) return min(a, b);
  float h = max(k - abs(a - b), 0.0) / k; return min(a, b) - h * h * k * 0.25; }
// 各ドロワーは「枠とだけ」なめらかに融合させ、ドロワー同士は普通の和集合にする
//(連鎖的に smin すると、近くのドロワー同士が細い橋でつながってしまうため)
float scene(vec2 p){
  float fr = -sdBox(p - (u_hole.xy + u_hole.zw * 0.5), u_hole.zw * 0.5, u_hole_r);   // 枠 = 窓の穴の外側
  float m = fr;
  for (int i = 0; i < 14; i++) {
    if (i >= u_n) break;
    vec4 b = u_box[i];
    m = min(m, smin(fr, sdBox(p - (b.xy + b.zw * 0.5), b.zw * 0.5, u_boxp[i].x), u_boxp[i].y));
  }
  return m;
}
```

1. **枠**は「窓を置く領域(穴)」の距離場を反転したものです(穴の外側が枠)。
2. 各**ドロワー**は角丸矩形の距離場です。
3. 枠とドロワーを `min`(和集合)ではなく **`smin`(なめらかな最小)**でつなぐと、付け根に**凹の丸み**ができます。ドロワーが縁から「生えてくる」ように見えるのはこのためです。`smin` の幅 `k`(`shell { frame-smoothing }`)で丸みの大きさが決まります。
4. **ドロワー同士は普通の `min`**: 全部を `smin` でつなぐと、近くにあるドロワー同士(右上の通知と右のサイドバーなど)が細い橋でつながってしまいました。各ドロワーは枠とだけ溶かします。

```glsl
void main(){
  vec2 p = vec2(v_uv.x, 1.0 - v_uv.y) * u_size;
  float m = scene(p);
  if (m > 36.0) discard;                       // 枠から遠い(窓の領域): 何も描かない
  float a = clamp(0.5 - m / px, 0.0, 1.0);
  float sh = u_shadow * exp(-max(m, 0.0) / 8.0) * (1.0 - a);   // 窓側に落ちる柔らかい影
  …
  // 法線(距離場の勾配)で屈折、縁のハイライト、ノイズ、きらめき — ガラスと同じ
  …
}
```

- **窓の領域は `discard`**(何も描かない)。全画面のサーフェスでも、実際に塗るのは縁の近くだけです。
- 枠の内側(窓側)には、距離に応じて指数的に薄くなる**影**を落とします。窓が枠の下に潜り込んでいるように見えます。
- ガラスの効果(真後ろの壁紙・屈折・縁の光・ノイズ・きらめき)は、[ガラス](#/tech-glass)と同じ計算を、この結合した形の距離場で行います。**ドロワーと縁の継ぎ目にも、同じ屈折と光が連続して**かかります。

**結果**: ドロワーの開き具合をばねで変えると、矩形の大きさが変わるだけで、付け根の丸み・影・屈折・光がすべて毎フレーム正しく計算し直されます。絵を用意する必要はありません。

## 窓に重ならないように: 幅 1px の透明サーフェス {#exclusive}

```zig
/// 縁の 4 辺に幅 1px の透明サーフェスを置き、排他領域だけを確保する
fn makeExclusions(self: *Frame) void {
    const specs = [4]struct { anchor: c_int, w: u32, h: u32, zone: f32 }{
        .{ .anchor = L | Tp | Bt, .w = 1, .h = 0, .zone = self.BW() * self.app.cfg.ui_scale },   // 左(縦バーの幅)
        .{ .anchor = Tp | L | Rt, .w = 0, .h = 1, .zone = self.T() * self.app.cfg.ui_scale },    // 上(枠の太さ)
        …
    };
    for (specs, 0..) |sp, i| {
        const s = Surface.createLayer(self.app, .{ .ctx = self, .draw = drawNothing }, .{
            …
            .exclusive = @intFromFloat(sp.zone),
            .namespace = "ame-frame-exclusion",
        }) catch continue;
        s.setInputRect(0, 0, 0, 0);
        …
    }
}
```

layer-shell の「排他領域(exclusive zone)」は、窓がその辺を避けて配置されるようにする仕組みです。ただし、**4 辺すべてに貼り付いた(全面の)サーフェスには排他領域を設定できません**(どの辺を避けるのかが決まらないため)。そこで、各辺に**幅 1px の何も描かないサーフェス**を置き、それぞれに排他領域だけを持たせています。入力領域も空なので、クリックは素通りします。

## ドロワーの開閉 {#drawer}

```zig
/// 1 つのドロワーの状態。t は開き具合(0..1、少し行き過ぎてから戻る)、w/h は中身の大きさ。
pub const Drawer = struct {
    open: bool = false,
    /// キー操作(ショートカット)で開いた。ホバーが外れても閉じない
    by_key: bool = false,
    t: Spring = Spring.init(0, 0.40, 0.70),
    w: Spring = Spring.init(0, 0.34, 0.88),
    h: Spring = Spring.init(0, 0.34, 0.88),
    …
};
```

- **開き具合 `t`** は少し弾むばね(減衰 0.70)。開くと少し行き過ぎてから戻ります。
- **中身の大きさ `w` `h`** は別のばね。ダッシュボードのタブを切り替えると、ドロワー自体の大きさがばねで変わり、中身はクロスフェードします。
- **ホバーで開く**: 縁(10px)にマウスが乗ったら開き、外れたら閉じます。ただし**キーで開いたもの**(`by_key`)は、マウスが外れても閉じません。
- 開いている途中で閉じても、ばねなので途中から自然に戻ります。

## 縦バーの「液体」のような印 {#liquid}

```zig
// src/frame/vbar.zig
lead: Spring = Spring.init(0, 0.20, 0.72),    // 先頭: 速い
trail: Spring = Spring.init(0, 0.42, 0.92),   // 後尾: 遅い
squish: Spring = Spring.init(0, 0.25, 0.5),
```

今のワークスペースの印は、**両端を別々のばね**で動かします。先頭は速く(0.20 秒)、後尾は遅く(0.42 秒)追いかけるので、移動中は印が**伸びて**、着いたら縮みます。液体のしずくが移動するように見えます。1 つのばねで動かすと、ただ平行移動するだけになります。

## データは「開いている間だけ」 {#data}

```zig
// src/frame/data.zig
// 枠 UI(caelestia 風)が使う追加のデータ源。全て「必要な間だけ」動かす:
//  * GPU/CPU 温度・GPU 使用率・ストレージ … ダッシュボードが開いている間の 1 秒ティックで読む
//  * 天気 … wttr.in を curl で非同期取得(30 分キャッシュ)。完了は pipe の EOF で知る
//  * cava(音声スペクトラム)… メディアタブ表示中だけ起動し、終わったら kill
//  * 電源プロファイル … powerprofilesctl(ユーティリティを開いたとき)
```

| データ | いつ動くか |
|---|---|
| CPU・GPU の使用率と温度・ストレージ | ダッシュボードが**開いている間だけ** 1 秒ごと |
| 天気 | 30 分キャッシュ。curl を非同期で起動し、終わったら pipe の EOF で知る |
| cava(スペクトラム) | メディアのタブを**表示している間だけ**プロセスを起動し、閉じたら kill |
| 電源プロファイル | ユーティリティを開いたときに 1 回 |

**ほかのシェルとの違い**: 多くのバーは、表示していなくても CPU 温度やスペクトラムを常に取り続けます。ame-shell は「見えていないものは取らない」ので、ダッシュボードを閉じている間は 1 秒ごとのタイマーも cava のプロセスも存在しません。

## ネットワークのパネル: コマンドを 1 つずつ {#netpanel}

```zig
// src/frame/netpanel.zig
// 裏では nmcli / bluetoothctl を「1 つずつ順番に」非同期で実行し(キュー)、完了は pipe の EOF で知る。
// 引数はシェルを通さず渡すので、SSID やパスワードにどんな文字が入っていても安全。
```

- **順番に 1 つずつ**: 実行中のコマンドが終わってから次を始めるので、スキャン中に「接続」を押しても、どの結果がどの操作のものかが崩れません。結果は 1 本の pipe で受け、EOF でコマンドの終わりを知ります。
- **シェルを通さない**: SSID やパスワードに `'` や `;` が入っていても、引数の配列として `execvp` に渡すので、コマンドとして解釈されることはありません(コマンドインジェクションの心配がない)。
- 接続に失敗したら、枠の縁が赤く光ります([エラーの光](#/tech-glass))。
