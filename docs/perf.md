# 性能の実測

計測環境: Ryzen 7 7735HS / Radeon 680M / Mesa 26.2.4 / ReleaseFast ビルド / ヘッドレス River 0.3.5(1280x720)内。
計測方法: `/proc/<pid>/stat` の utime+stime 差分(10 秒)、`/proc/<pid>/status`・`smaps_rollup`、`ame-ctl stats`(シェル内蔵のフレーム統計)、`AME_DEBUG_FRAMES=<ms>`(遅いフレームの内訳)、`AME_DEBUG_MEM=1`(起動段階ごとの RSS)。

## 予算(hardware.md を受けて調整)

| 項目 | 初期値 | 調整後 | 理由 |
|---|---|---|---|
| 待機時 CPU | < 0.5% | < 0.5%(ライブ壁紙 OFF)、< 2%(ライブ壁紙 ON) | 16 スレッド CPU。壁紙は GPU 側が主 |
| 常駐メモリ | RSS < 80MB | **PSS < 80MB / 私有(anon) < 60MB** | 下記: GL スタックだけで RSS 78MB |
| 起動 → バー表示 | < 300ms | < 300ms | |
| フレーム時間 | 1 フレーム予算内 | 60Hz: < 16.6ms(初回のみ除く) | パネルの出力は 60Hz |

## 結果

| 項目 | 実測 | 判定 |
|---|---|---|
| 待機時 CPU(壁紙静止 `animate off`) | 0.0〜0.1%(10 秒で 0〜1 tick) | ✅ |
| 待機時 CPU(オーロラ 30fps) | 1.1% | ✅(調整後予算) |
| 待機時 CPU(雨 60fps) | 1.0% | ✅ |
| 起動 → 最初のバーのフレーム | 92〜160ms | ✅ |
| 描画 1 回の CPU 時間(平均) | 0.8〜1.1ms | ✅ |
| 描画 1 回の最大(先読み完了後、ランチャー/ダッシュボード/通知を初めて開く操作を含む) | 9.9ms | ✅ |
| 起動直後のバー初回フレーム | 23ms(1 回だけ。先読み前のグリフ生成) | 許容 |
| RSS(待機) | 126〜137MB | ❌ 初期予算(80MB)は未達 |
| PSS(待機) | 69〜75MB | ✅(調整後予算) |
| 私有 anon(待機) | 57〜60MB | ✅(調整後予算、ただし下記の未解決あり) |

### メモリの内訳(`AME_DEBUG_MEM=1`)
- exec 直後(EGL 初期化前)で既に RSS 51MB: Mesa の libgallium が libLLVM(RSS 約 45MB、他の GL プロセスと共有)をリンク時にロードするため。
- EGL 初期化 +27MB、フォント(CJK 2 書体 + Nerd Font)+9MB、サーフェス作成後 89MB、最初の描画(ドライバのシェーダコンパイル等)で約 108〜127MB。
- RSS のうち約 70MB はファイルに裏打ちされた共有ライブラリ。システム全体のコストを表すのは PSS。
- 改善済み: グリフアトラスを CPU で 0 埋めして転送していた分(+11MB)を GPU クリアに変更。
- **未解決**: 私有 anon が途中の版では 37MB だったが、現在 57〜60MB。アトラスサイズ・SDF 方式の差ではないことを確認済み。原因の切り分けは `docs/blockers.md`。

### 遅いフレームの調査記録
| 現象 | 原因 | 対策 | 結果 |
|---|---|---|---|
| ランチャー初回 525ms | アウトライン SDF が 1 字 6.6ms × 約 100 字 | bsdf 化(2.2ms/字)+ アイドル先読み | → 0 字生成 |
| ランチャーで 92ms | `zellij.png`(巨大)のデコード | ワーカースレッドで 64x64 に縮小 | → 描画スレッドから消滅 |
| ダッシュボード初回 19ms | アイコン等 9 字の未生成グリフ | 先読み対象に UI の Nerd アイコンを追加 | → 9.9ms 以下 |
| アトラス拡張時のスパイク | 拡張でキャッシュ全消去 | 最初から 2048² | → 拡張なし |

## 再現手順
```sh
zig build -Doptimize=ReleaseFast
# ネストした River で起動して
ame-ctl stats
# 遅いフレームの内訳(8ms 超を出力)
AME_DEBUG_FRAMES=8 ame-shell
```
