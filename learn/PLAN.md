# 学習サイトの計画(PLAN)

目的: 学習者が **AI なしで** 同じようなデスクトップシェルを書け、障害を自力で切り分けて直せるようになること。
サイトは教材。成功の基準は「できるようになったか」だけ。

---

## 1. 監査: 今のサイトと docs の何が分かりにくいか(Phase 0)

数値は `site/src/content` と `docs/` を awk で数えたもの(コードブロックを除く。2026-11-11)。

| 問題 | 根拠 | 学習サイトでの対策 |
|---|---|---|
| **図・デモが無い** | 技術解説 21 ページすべてで図・デモが 0。図があるのはホーム・アニメーション・機能の 3 ページだけ | 1 ページに主役の図を 1 つ。できる限り実コードを WASM で動かす図 |
| **1 ブロックが長い** | 段落の最長が 200〜330 字(6〜10 行)。`shell.md` の箇条書き 1 項目が 910 字 | 1 ブロック 5 行以内。表と箇条書きに分ける |
| **手を動かす場所が無い** | 演習・確認テスト・チェックリストが 0。「自分で確かめる」コマンドは一部のページだけ | 全ページに 予測 → 実験 → 演習 → 確認テスト → 確かめるコマンド |
| **次に何をするかが無い** | ページの終わりに「次」が無い。読む順が決まっていない | 「今日やること 1 つ」「次のページ」を上と下に固定 |
| **用語で別ページへ飛ぶ** | 用語は Wiki へのリンク(押すと今のページを離れる)。1 ページに 5〜12 個 | その場で開く用語の説明(`{{語|説明}}`)。Wiki は「もっと知りたい人へ」 |
| **自動で動く** | 既存のばねのデモは触らなくても動き続ける(注意を奪う) | 学習のデモは、押したときだけ動く。再生 / 一時停止 / コマ送り / 速度 |
| **前提の数学が飛ぶ** | `anim.md` は ω・ζ・半陰的オイラー法を 1 段落で導入する | 不変条件 → 直感 → 図 → 小さな手計算 → 式 → コード の順に、1 回 1 つ |
| **docs は作者向けのメモ** | `decisions.md` は「決定 / 理由 / 却下」だが 1 行に詰めてある。`progress.md` は段落 566 字 | L4 で 1 項目ずつ「なぜ却下か」を問題にする(読ませるのではなく答えさせる) |
| **主張を確かめる手段が無い** | 計測値(待機 CPU 0.0〜0.1% など)はあるが、その場で再現する手順が散らばっている | 各ページに「自分で確かめる」(BSD 系のコマンドで動くもの)を必ず付ける |

良いところ(残す): 各技術ページの冒頭の「このページを読む前に」(:::easy)、実コードの抜き出し、計測に基づく説明、anim.wasm で実コードを動かす仕組み。

## 2. 到達レベルと修了テスト

各レベルの修了テストは「AI なし・ヒントなし」で行う。ページごとのチェックリストがその部品。

| レベル | できること(修了テスト) |
|---|---|
| L0 動かせる | `zig build -Doptimize=ReleaseFast && zig build test` を通す。ヘッドレスの River で ame-shell を起動し、スクリーンショットを撮り、`ame-ctl stats` とログを読む |
| L1 読める | 描画 1 フレームの流れ(状態変化 → `Surface.schedule()` → frame done → `render(dt)` → 次を頼む / 止まる)を図にして 3 分で説明する |
| L2 直せる | 故障を仕込んだコードの原因を特定して直す(障害ラボ初級) |
| L3 書ける | `spring_step`・ファジー検索のスコア・LRC パーサを白紙から書き、与えたテストを通す |
| L4 設計できる | `docs/decisions.md` の各項目の「却下した案」の理由を説明し、性能予算(待機 CPU・フレーム時間・メモリ)を自分で測る |
| L5 自立 | 未知の障害を、再現 → 切り分け → 修正 → 再発防止テストまで 1 人で終える |

## 5. 1 レッスンの型(全ページ共通)

1. 所要時間・できるようになること(1 行)・前提 2. 3 行要約 3. 予測(答えは隠す)
4. 触れるデモ(実コードを WASM で) 5. 直感 → 図 → 式 → コード 6. コードの場所(ファイル:行)
7. 演習: 穴埋め → 一部空白 → 白紙。ヒント 4 段階(方向 / 関連箇所 / 擬似コード / 答え)を折りたたむ
8. 確認テスト 3 問(答えは隠す) 9. 自分で確かめるコマンド 10. つまずいたとき 11. できたチェック・翌日の復習 3 問

ADHD への配慮: 1 ブロック 5 行以内・主役の図 1 つ・「今日やること」「次」を固定・進捗・続きから再開・メモ(localStorage だけ)・集中モード・動きを減らす・自動再生しない・点滅しない・色だけで意味を伝えない。

## 6. 置き場所と仕組み

| もの | 場所 | 動かし方 |
|---|---|---|
| レッスンの本文 | `site/src/content/learn/*.md` | `zig build site` |
| 演習・ラボのコード | `learn/<題>/` | `zig test learn/<題>/<ファイル>.zig` |
| 実物の Odin との突き合わせ | `learn/check-real.sh` | `sh learn/check-real.sh`(anim.o を作って同じ不変条件を本物に当てる) |
| コードの参照の検査 | `learn/tools/refcheck.zig` | `sh learn/tools/refcheck.sh`(本文の「ファイル:行 名前」が実在するか。Zig 0.13 で動かす) |

アプリ本体(`src/`・`anim/`・`widgets/`)は変えない。教材の言語は Zig(と既存の Odin)、スクリプトは POSIX sh。

---

## 7. 正確さの担保

- 本文の数値は、すべて手元で計測してから書く(Phase 1 の数値: `learn/spring/measure_test.zig` で再現できる)。
- コードの参照は `refcheck` で自動検査する。
- 確かめていないことは「未検証」と書く。

## 8. 進め方

- Phase 0(この文書)→ **Phase 1: `learn/spring` の 1 本だけ**を作り、学習者が試して合否を出すまで止まる。公開もその後。
- Phase 2: 合格したら、レベル順に 1 コミット = 1 レッスン。
- Phase 3: 障害ラボ・白紙再実装・復習カードの仕上げ。必要なら推論(ame-hand・ame-face)のステージ。
